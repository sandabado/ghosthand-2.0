# V4 Drain — focused verification plan

Approved D06/D07 govern this pass: blue belongs to the leeching filaments; the liberation dawn uses candle green. FALL's orientation remains fixed. Look up is a deliberate upward gesture inside the dedicated interaction area, with an equivalent keyboard path. Ordinary scrolling never releases the threads. No new grade, camera verb, scene, or sword moment is introduced.

## Geometry and ownership checks

Run `node scripts/verify-drain.mjs` after the renderer is integrated. The focused checks should establish finite deterministic paths/transforms, nonzero segment lengths, camera-body roots rising toward distant anchors, fixture-index coverage and bounds, reversible instance/strand/audit mapping, bounded monotonic per-strand release, seeded variety, and shared clock/composer ownership. These checks do not prove GPU raycast accuracy or visual quality.

## Browser journey checks

1. Enter Drain normally from Threshold and Legend. Confirm one live Canvas/composer/heartbeat and the intended first-person filament field. Record real live counts, not only JSX declarations.
2. Move the pointer over a visible projected filament target. Confirm an actual raycaster hit changes the selected fixture name/rate/meaning. Record the hit count/instance mapping. Compare at least two different fixture indices. Keep source audit values clearly illustrative.
3. Focus/select an audit entry with the keyboard. Confirm a stationary pointer does not steal selection. Touch users must retain an accessible audit control even without hover.
4. Scroll the page and inner readable panel. Neither operation releases the threads or changes FALL's camera orientation.
5. Click/tap the gesture area without travel; make a short upward stroke; make a predominantly sideways/downward stroke; cancel a pointer capture; blur the gesture target. None commits release or leaves a deferred armed state.
6. Make a sufficiently long, predominantly upward pointer/touch gesture inside the dedicated area. Confirm the same release path as ArrowUp/keyboard activation. Capture the tension, early cascade, late dissolution, and green dawn states. The camera orientation remains fixed in every sample.
7. Confirm filaments recoil/dissolve in a staggered cascade rather than all scaling down at once. Leeching pulses stop. The candle-green dawn develops as a local scene effect and remains visually distinct from the bound gray/blue state.
8. During release, explicit next-step and end-of-scroll advancement remain guarded until the release has settled. After settling, keyboard and pointer advancement both lead to Craft F1.
9. Reset/re-enter and repeat via the keyboard alternative. Confirm the same state/parameter destination and no stale audit/gesture/release state.
10. Load with reduced motion. Confirm a static bound/released representation, all fourteen storyboard states, reachable audit/Look up controls, no camera or atmospheric movement, and no long animated hold before advancement.
11. Check 320/390px and desktop widths for horizontal overflow, readable audit tooltip, reachable gesture and Next controls, and no UI pointer block over all filament targets.
12. Continue through the four existing gate fixtures to Merge/Fork. Confirm unchanged locked timing, silence, allowed sword accounting, and persistent path navigation.

## Evidence distinctions

The final receipt should separate source checks, actual raycast/interaction observations, static export bytes, and GPU/device performance. A ticker rate is not rendered/presented FPS. Viewport emulation is not a physical mid-tier mobile benchmark. The source package supplies no final environment-only Drain plate or production audio; authored geometry and the existing illustrative audit list must not become factual visitor-cost or outcome claims.

Human visual review follows v4. Do not start v5 or public launch from this plan.
